## How the Index File Works

The index JSON file stores everything needed for searching:

```json
{
  "document": "AAPL-10K.txt",
  "indexed_at": "2026-03-15T14:30:00Z",
  "model": "nomic-embed-text",
  "sections": [
    {
      "id": 0,
      "title": "Item 1: Business — Overview",
      "text": "Apple Inc. designs, manufactures, and markets smartphones...",
      "char_count": 4250,
      "embedding": [0.023, -0.041, 0.018, ...]
    },
    {
      "id": 1,
      "title": "Item 1: Business — Products and Services",
      "text": "iPhone. iPhone is the Company's line of smartphones...",
      "char_count": 3100,
      "embedding": [0.015, -0.033, 0.042, ...]
    }
  ]
}
```

Key points:
- **Section titles are preserved.** Each piece knows which part of the
  document it came from.
- **Vectors are stored.** You don't recompute them every time you
  search — the index is built once and reused.
- **The file describes itself.** It records which model was used and
  when, so you know if you need to re-index.

## MCP Tool: `search_document(query, doc_name)`

**What it returns:**

```json
{
  "query": "What are Apple's main risk factors?",
  "document": "AAPL-10K",
  "results": [
    {
      "section_title": "Item 1A: Risk Factors — Macroeconomic Risks",
      "excerpt": "The Company's operations depend significantly on worldwide economic conditions...",
      "similarity_score": 0.84,
      "confidence": "high",
      "section_id": 5
    },
    {
      "section_title": "Item 1A: Risk Factors — Legal and Regulatory",
      "excerpt": "The Company is subject to complex and changing laws...",
      "similarity_score": 0.79,
      "confidence": "high",
      "section_id": 6
    },
    {
      "section_title": "Item 1A: Risk Factors — Technology Risks",
      "excerpt": "The Company's products may be affected by new technologies...",
      "similarity_score": 0.76,
      "confidence": "high",
      "section_id": 7
    }
  ],
  "result_count": 3,
  "data_source": "local_ollama",
  "as_of": "2026-03-15T14:35:00Z"
}
```

**What's smart about this:**

- **Confidence labels** (high/medium/low) help the AI know which
  results to trust most.
- **Excerpts, not full text.** The search returns just the first ~200
  characters. The full text goes to the AI in `ask_document`.
- **Section titles** tell you exactly where in the document each
  result came from.

## MCP Tool: `ask_document(question, doc_name)`

**What it returns:**

```json
{
  "question": "What are Apple's main risk factors related to AI?",
  "document": "AAPL-10K",
  "answer": "According to Item 1A (Risk Factors — Technology Risks), Apple identifies several AI-related risks: the company's products may be affected by rapid technological changes including AI, and the company faces competition from others investing heavily in AI. The filing also notes under Legal and Regulatory that evolving AI regulations could impact operations.",
  "citations": [
    {
      "section_title": "Item 1A: Risk Factors — Technology Risks",
      "section_id": 7,
      "relevance": "high"
    },
    {
      "section_title": "Item 1A: Risk Factors — Legal and Regulatory",
      "section_id": 6,
      "relevance": "medium"
    }
  ],
  "model_used": "qwen3.5:4b",
  "data_source": "local_ollama",
  "as_of": "2026-03-15T14:35:00Z",
  "note": "Answer generated by local model from indexed document sections. No data sent to cloud services."
}
```

**What's smart about this:**

- **Citations link to sections.** Each claim in the answer points to a
  specific part of the document. You can verify what the AI says.
- **Model disclosure.** It tells you which model generated the answer.
  Local models (even the 9b) aren't as smart as Claude — the answer
  quality reflects this.
- **Privacy note.** The explicit statement that no data left the machine
  is important for anyone concerned about privacy.

## MCP Tool: `get_rag_guide()`

```json
{
  "overview": "Local document Q&A system using Ollama. All processing happens on this computer — no data is sent to the cloud.",
  "tools": {
    "index_document": "Index a new document. Takes 1-3 minutes for a full annual report. Only needs to be done once per document.",
    "list_documents": "See all indexed documents with section counts.",
    "search_document": "Search a document for relevant sections. Good for browsing.",
    "ask_document": "Ask a question about a document. Gets a cited answer using the local AI."
  },
  "recommended_flow": [
    "1. index_document(file_path) — index the document (one-time)",
    "2. list_documents() — check it was indexed",
    "3. search_document(query, doc_name) — browse for relevant sections",
    "4. ask_document(question, doc_name) — get a cited answer"
  ],
  "important_notes": [
    "All processing uses local Ollama models — no cloud services involved",
    "Answers from the local model aren't as polished as Claude. Use them as starting points.",
    "Citations reference specific document sections — always check the source",
    "If Ollama is not running, tools will return an error with instructions"
  ]
}
```

**The honesty note matters.** The guide tells Claude Desktop that local
model answers are "not as polished" and should be used as "starting
points." This prevents Claude from presenting a rough local answer as
a definitive analysis.

## The Hybrid Pattern in Action

Here's what happens when you ask Claude Desktop "What does Apple's
annual report say about AI risk, and how is AAPL doing today?":

```
1. Claude calls ask_document("AI risk", "AAPL-10K")
   → Your RAG server searches locally via Ollama
   → Returns cited sections about AI risk (local, private)

2. Claude calls get_stock_snapshot("AAPL")
   → Your Week 1 server fetches live data via yfinance
   → Returns current price and daily change (from the internet)

3. Claude puts it together:
   "Apple's annual report identifies AI regulation as a key risk
   factor (Item 1A). Meanwhile, AAPL is up 0.85% today at $195.20."
```

The document search was completely local — no data left your computer.
The stock data came from a free internet source. Claude's intelligence
tied them together. This is the hybrid approach — privacy where it
matters, cloud capabilities where they're needed.

## How Fast Is It?

Speeds depend on your model and computer:

| What's Happening | 0.8b (8GB) | 4b (16GB) | 9b (32GB) |
|-----------------|-----------|----------|----------|
| First call (model loads) | 2-5 sec | 5-10 sec | 10-20 sec |
| Creating one section vector | < 1 sec | < 1 sec | < 1 sec |
| Indexing a full annual report | 1-2 min | 1-3 min | 1-3 min |
| Searching | < 1 sec | < 1 sec | < 1 sec |
| Generating an answer | 3-8 sec | 5-15 sec | 10-30 sec |

The first call is slow because Ollama loads the model into memory.
After that, everything is faster. If your computer feels slow, close
other apps or try a smaller model.
