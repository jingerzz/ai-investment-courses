# Course Brief — CoWork Handoff Document

This file provides the metadata, structure, and design direction needed
to transform the course folder into polished marketing materials and a
PDF-style learning book.

---

## Audience

**Primary:** Investment analysts, portfolio managers, IT managers at
investment firms.

**Profile:**
- Deep finance and markets knowledge — do not explain financial concepts
- Little to no programming experience — they will not write or read code
- Comfortable with desktop software; willing to learn CLI basics
- Motivated by practical workflow improvement, not technology for its own sake

**Tone:** Professional but approachable. Think "senior colleague showing
you a new tool" — not a textbook, not a blog post.

---

## Value Proposition

Finance professionals learn to build AI-powered tools for their daily
workflows — without writing code. They describe what they want in plain
English, and Claude builds it. By the end, they have working tools
connected to real market data that they built themselves.

**One-liner:** *Build AI tools for investment management — no coding required.*

---

## Learning Outcomes

| Week | Outcome |
|------|---------|
| 1 | Install and use pre-built MCP servers (SPY/TLT strategy). Experience AI tools backed by real market data. Understand the tool-use pattern, MCP, and four design principles. |
| 2 | Build your own MCP server with Claude Code. Add guardrails (pre-formatted templates, stale data warnings). Set up Ollama and a structure-first RAG system for SEC filing Q&A. |
| 3 | Design a multi-server architecture for your organization. Understand separation of concerns, shared libraries, and deployment. |
| 4 | Build an agent workflow with approval rules and audit trails. Understand autonomy levels and compliance requirements. |

**Cumulative outcome:** Participants can evaluate, commission, and oversee
AI tool development at their firms — even if someone else writes the code.

## Design Direction

### Visual style
- Clean, professional — suitable for a finance audience
- Minimal color palette; avoid "techy" or startup aesthetics
- Code blocks and JSON examples should be visually distinct but not dominant
- Tables are used heavily — make them clean and readable

### Content treatment
- **Reading sections** are the core chapters — present as continuous prose
- **Conversation guides** should become callout boxes or sidebars within
  exercises (e.g., "Example Prompt" or "Try This" boxes)
- **Checklists** should appear at the end of each chapter as a self-assessment
- **Reference solutions** can be appendices or expandable/foldable sections
  — they're for checking your work, not primary reading
- **JSON examples** appear frequently — format them consistently with
  syntax highlighting

### Recurring elements to style consistently
- **Prompt examples** — blocks showing what to type into Claude Code
- **Tool return examples** — JSON blocks showing what MCP tools return
- **Design decision callouts** — explanations of why something was built
  a certain way (these appear in reference solutions)
- **Guardrail patterns** — recurring theme; consider a visual motif
- **"What Claude does vs. what your code does"** — recurring comparison;
  consider a two-column layout or icon system

### Chapter structure (suggested)
Each chapter should follow this flow:
1. Opening — why this matters (1-2 paragraphs)
2. Concepts — the reading material
3. Exercise — hands-on with Claude Code
4. Example prompts — what to say to Claude (from conversation guide)
5. Self-check — the checklist
6. Reference — what a good result looks like (collapsible/appendix)

## Marketing Materials — Key Messages

**Headlines (pick/adapt):**
- "Build AI Tools for Investment Management — No Coding Required"
- "From Idea to Working Tool in 30 Minutes"
- "AI-Powered Investment Analysis: A Hands-On Course for Finance Professionals"

**Key selling points:**
1. No programming required — Claude builds everything from plain English
2. Real market data — not toy examples; uses Yahoo Finance, SEC EDGAR
3. Privacy-aware — local model option for sensitive documents
4. Production patterns — guardrails, audit trails, approval workflows
5. Cumulative build — each week extends the previous week's work
6. 30 + 30 format — manageable weekly commitment (30 min reading, 30 min hands-on)

**What this is NOT:**
- Not a coding bootcamp
- Not a finance course (assumes finance knowledge)
- Not theoretical — every week produces a working tool
- Not vendor-locked — teaches patterns applicable beyond Claude/Anthropic
